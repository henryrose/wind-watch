# Wind Watch — implementation plan (multi-agent)

Written 2026-10-21. Inputs: `InitialPrompt.md`, `docs/DESIGN.md` (architecture, API contract),
`docs/WINDWATCH-DESIGN-HANDOFF.md` (UI contract; wins over the canvas). This plan is executed
by an orchestrator loop (`docs/LOOP_PROMPT.md`) that dispatches subagents and records state in
`progress.md`. Nothing in this plan requires the other machine until §7.

## 0. Contract reconciliation (decided here, binding on every agent)

The two design docs describe the payload at different layers. Both are right; they are not the same object.

| Layer | Source of truth | Shape |
|---|---|---|
| **Wire payload** (server → clients, web) | `DESIGN.md` §4.2 | compact: `v, loc, model, fetched, run{latest,extended}, start, hours:Int, kn[], gust[], dir[], peak, summary, sun[]` |
| **Forecast view model** (what UI code reads) | `HANDOFF.md` §2 | `location{name,lat,lon,isDefault}, run:"HRRR 15Z", fetched, start, horizon, hours:[{kn,gust,dirFrom}], sun[], summary, peakGust` |

Derivations, implemented once in `WindCore` (Swift) and once in `web/` (JS), tested against the same fixture:

- `run` label = `"HRRR " + String(format: "%02dZ", utcHour(run.latest))`.
- `horizon = start + (hours − 1) × 3600`.
- `hours[i] = { kn: kn[i], gust: gust[i], dirFrom: dir[i] }`.
- `location.isDefault` is device state, not wire state (`loc.cell == "sea"` and no custom location selected).
- `peakGust = { kn: peak.gust, at: peak.at }`.
- Trust state, `nowIndex`, hero, age tiers: HANDOFF §2–3 verbatim.
- Timeline entries: one per hour boundary to `horizon`, plus `fetched + 90 min` and `fetched + 6 h` (HANDOFF §7.1), plus a final past-horizon entry (DESIGN §5.2).

Other binding decisions:

- Open decision 1 (HANDOFF §12): keep the six-bar strip on the rectangular complication.
- Open decision 2: hold the Smart Stack widget; do not build it in v1.
- Open decision 3: keep "G" everywhere.
- Deployment targets: iOS 26.0, watchOS 26.0. SDK is whatever Xcode 27 ships; that is fine.
- Project file: generated by XcodeGen from `apple/project.yml`, **and the generated `.xcodeproj` is committed** (Henry wants it checked in; the yml is the editable source). Regenerate with `xcodegen generate` after changing targets.
- Shared fixture: `fixtures/payload-reference.json` at repo root, in wire format, built from HANDOFF §10. Server tests, Swift tests, and the web page's offline mode all load it.

## 2. Workstreams and agents

One subagent per workstream at a time. Workstreams own disjoint paths, so up to three run concurrently without conflicts. Agents **never commit and never edit `progress.md`**; the orchestrator verifies and commits.

| Agent | Workstream | Owns | Reads first |
|---|---|---|---|
| `server` | B | `server/**`, `fixtures/openmeteo-*.json` | DESIGN §2, §4, §5.2 (for skip logic) |
| `core` | C, then D | `apple/**` | DESIGN §4–8, HANDOFF all sections |
| `web` | E | `web/**` | HANDOFF §1–6, §9, §10; DESIGN §4.2 |
| orchestrator | A, F | root files, `docs/**`, `fixtures/payload-reference.json`, `progress.md` | everything |

Subagent type: `general-purpose`. Each brief in §3 is self-contained; the orchestrator pastes it plus the "Rules for every agent" block in §5.

### B — Server (agent `server`)

**B1 Scaffold + transform.** `server/package.json` (pnpm, `wrangler`, `vitest`, `@cloudflare/vitest-pool-workers`, `typescript`), `wrangler.toml` (name `wind-watch`, `main = src/index.ts`, `[triggers] crons = ["*/10 * * * *"]`, a `[[kv_namespaces]]` binding `WIND` with `id = "REPLACE_ON_DEPLOY"`), `tsconfig.json`, `src/transform.ts`: `(forecastJson, metaJson, now) → Payload`. Rules: truncate at the first null, round to Int, `run.latest` from meta, `run.extended = horizonEnd − 48 h` only when it differs from latest by a multiple of 6 h else null, peak gust = max gust and its time (first occurrence), `loc` from the request constants.
Tests: fixture → 45 hours, ints, horizon end matches, peak = 25 at the expected index, run inference, payload serialises under 1,000 bytes.
Verify: `cd server && pnpm install && pnpm test`.

**B2 Sun.** `src/sun.ts`: NOAA solar position; `sunEvents(lat, lon, utcDay) → {dawn, rise, set, dusk}` (civil = −6°). Emit one entry per local civil day touched by `[start, horizon]` using the payload `tz`. Tests: Port Townsend 2026-10-21 rise/set within ±3 min of 07:40/18:12 PDT and dawn/dusk within ±3 min of 07:08/18:44; add `suncalc` as a dev-dependency oracle for three other lat/lon/dates.
Verify: `pnpm test`.

**B3 Summary.** `src/summary.ts`: rule-based one sentence ≤ 110 chars. Rules: describe the first 3 h (calm `< 7`, light `7–10`, moderate `11–16`, fresh `17–21`, strong `22+`) with 8-point compass; if a later 6-h window's mean exceeds now by ≥ 5 kn, add "building to N kn DIR by <period>"; mention `gusts to G` if peak gust ≥ 15; add "easing by <period>" if the last 6 h mean is ≥ 5 kn below the peak window. Periods: morning/afternoon/evening/overnight/dawn/tomorrow morning… from local hour. Tests: reference payload yields something sane and ≤ 110 chars; a flat-calm payload yields "Calm through tomorrow." style; never produces decimals.
Verify: `pnpm test`.

**B4 Handlers.** `src/index.ts`. `scheduled`: fetch meta → compare `last_run_availability_time` with `KV:default:meta` → if changed, fetch forecast, transform, write `KV:default` = body and `KV:default:etag` = `"sha256-<16 hex>"` and the meta value. `fetch`: `GET /v1/wind` → KV read, headers per DESIGN §4.4, 304 on `If-None-Match`, 503 `no_data` if empty; `GET /v1/wind?lat&lon` → validate, round to 2 dp, `caches.default` lookup with a 10-min TTL, upstream fetch with `cell_selection=nearest&timezone=auto`, same transform, 502 `upstream` on failure; anything else 404. Tests with the Workers vitest pool and a mocked upstream (`fetchMock`): first scheduled run writes KV; second with same meta skips; GET returns 200 then 304; custom path validates. Local run: `pnpm wrangler dev --test-scheduled`, `curl "http://localhost:8787/__scheduled?cron=*/10+*+*+*+*"`, then `curl -i localhost:8787/v1/wind` returns 200 with `ETag`, and `curl -i -H 'If-None-Match: <etag>' …` returns 304.
Verify: `pnpm test` and the `wrangler dev` curl sequence (orchestrator runs it, kills the dev server after).

**B5 Server README.** `server/README.md`: one-time setup on the deploy machine (`pnpm install`, `pnpm wrangler login`, `pnpm wrangler kv namespace create WIND`, paste the id into `wrangler.toml`, `pnpm wrangler deploy`, trigger once via `pnpm wrangler cron trigger` or wait 10 min, `curl` the `workers.dev` URL), the redeploy command, how to read logs (`pnpm wrangler tail`), and what to put in `apple/Config/Shared.xcconfig` (`WW_API_BASE`) and `web/config.js`.
Verify: orchestrator reads it and confirms every command exists in `package.json` scripts.

A3 → C1 → C2 → C3 → C4 → C5          (agent core, serial)

## 5. Rules for every agent (paste into every brief)

- Read `docs/DESIGN.md` and `docs/WINDWATCH-DESIGN-HANDOFF.md` sections named in your task before writing code. The handoff doc wins over the canvas; `docs/IMPLEMENTATION_PLAN.md` §0 wins over both where they differ.
- Touch only the paths your workstream owns. Do not edit `progress.md`, `CLAUDE.md`, or anything under `docs/`. Do not commit. Do not push.
- For anything under `server/` or `web/`, run `export PATH="$HOME/.nvm/versions/node/v24.13.0/bin:$PATH"` first. Use `pnpm`, never `npm`.
- Never hardcode a team id, bundle prefix, KV id, or API URL; use the xcconfig / `wrangler.toml` placeholders / `config.js`.
- Integers in knots everywhere. Arrows rotate `dirFrom + 180`. Stale data is labelled. The chart ends at the horizon.
- Run your task's verification command yourself before reporting. Report: files changed, the exact verification command and its last 20 lines of output, anything you could not verify and why, and any decision you made that the docs did not settle.
- If the task is impossible as written, do the possible part, then say precisely what is blocked.

## 6. Verification standard (orchestrator)

A task is `done` only when the orchestrator has re-run the verification command itself and it passed, and, for UI tasks, has looked at the screenshots. Agent claims are inputs, not evidence. Each `done` task gets one commit: `<ID>: <one line>` with the attribution trailer. Decisions an agent made are copied into `progress.md` → Decisions. Anything needing Henry goes to `progress.md` → Questions for Henry, and the loop proceeds on the plan's default.
